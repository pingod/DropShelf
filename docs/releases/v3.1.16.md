DropShelf 3.1.16 把从置物架拖文件到微信、WPS 协作的结果都对上了：图片变成图片消息，文件不会再莫名其妙变成剪贴板里的内容。

### Linux 版

- **图片拖进微信变成图片消息**：单张图片拖出时，除了文件列表再附一份 `image/png`（JPEG 给 `image/jpeg`）。微信这类聊天程序只认图片格式，以前拿到文件列表只会贴出乱码和“PNG”标签，现在直接发成图片。别的程序照旧拿文件，行为不变。
- **文件拖进微信不再粘出剪贴板**：文件列表提供的是 `text/plain;charset=utf-8`，微信找的是不带 charset 的 `text/plain`，找不到就退回去粘贴剪贴板。现在拖非图片文件时额外给一份纯 `text/plain`（文件路径），微信会把路径当文字插进输入框。微信这个客户端不支持把文件当附件收，路径文字是它能做到的上限。
- **X11 拖动源认得出微信的窗口**：微信把自己的 `_NET_WM_PID` 写成了 22、`XdndAware` 的属性类型也不规范。以前按 pid 找不到接收窗口就退回 Hyprland 的拖动桥，而它在 Wayland→XWayland 落手时会把拖动数据换成剪贴板内容。现在 pid 对不上时按窗口位置和大小兜底匹配（容差 64 像素），认出后由置物架自己把数据递过去。
- **图片按原始字节送出、大图完整送达**：X11 拖动源会把图片原文件按 `image/png` / `image/jpeg` 给出去；分段发送（INCR）改成按长度拷贝，二进制里出现 0 字节也不会被截断。
- **WPS 协作**：图片和文件都能正常落下（本版验证过）。
