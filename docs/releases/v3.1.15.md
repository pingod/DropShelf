DropShelf 3.1.15 把拖放收尾时可能丢内容的几处补上了：自动分批没送完、上一次拖出没收完就接着拖、拖入被置物架拒掉、很长的文字一次塞不下。

### Linux 版

- **自动分批没全部送到时项目留在架上**：以前只要第一批放下了，置物架就按“移动”把整组项目收掉；后面几批被接收方拒绝或者超时没送出去时，那些文字已经不在了。现在只要有批次没送出去，这次拖出就按取消收尾，项目全部留在置物架上，由你自己处理。
- **新的一次拖动不会送出上一次的内容**：接收方没回结束通知时，上一次拖出会挂一会儿；这期间马上开始的拖动以前会沿用上一次的文件和文字（甚至上一次的复制/移动判断）。现在准备新内容前会先把上一次收尾，并把内容清掉。
- **拖入没被收下时明确回绝**：置物架正忙、图片解不开这类情况以前也回“放下成功”，来源程序按移动提议的话会把原文删掉。现在回 XdndFinished 失败，来源会保留原文。
- **很长的文字改成分段发送**：X 的一次请求塞不下超过约 256 KB 的数据，以前拖很长的文字到 WPS 这类程序时对方什么都收不到。现在超过一块就按 ICCCM 的 INCR 一段一段地送，内容完整到达。
- **格式用不上的拖入马上回绝**：以前不回 XdndStatus，铺满屏幕的接放窗口要多挂一会儿（松手后 1.5 秒），期间的点击可能被它吃掉。现在立刻回绝并收掉。
- **读不到全局按键时也能松手**：拿不到输入设备权限时，自己的 X11 拖动源以前永远等不到“左键松开”，要 30 秒超时才取消。现在退回问 X 的按键状态，正常放下。
- **拖出时查询窗口少一些**：拖出期间问 Hyprland 光标底下是不是 X11 程序的频率从每 50 毫秒一次降到每 200 毫秒一次，拖动更轻。

DropShelf 3.1.15 closes several ways content could be lost at the end of a drag: unfinished auto batches, a new drag started before the previous one finished, drops the shelf refused, and very long text that did not fit in one X request.

### Linux

- **Items stay on the shelf when auto batches did not all arrive**: previously one successful first drop made the shelf remove the whole set in Move mode, even when later batches were refused or timed out — those items were gone. Now any undelivered batch turns the drag into a cancellation and every item stays on the shelf for you to handle.
- **A new drag no longer sends the previous drag's content**: when the receiver never sent the end notification, the old drag stayed in flight; a new drag started in that window used to inherit the old files and text (and the old copy/move decision). The old drag is now finished and its payload cleared before the new one is prepared.
- **Refused drops are reported as failures**: a busy shelf or an undecodable image used to answer "dropped successfully" as well, so a source that proposed a move could delete its original. It now answers XdndFinished false and the source keeps its data.
- **Long text is sent in chunks**: one X request cannot carry more than roughly 256 KB, so dragging very long text into apps like WPS used to deliver nothing. Data beyond one chunk now goes through ICCCM's INCR transfer and arrives complete.
- **Unsupported drags are refused at once**: without an XdndStatus answer, the full-screen drop window used to linger (1.5 s after release) and could swallow clicks. It now refuses immediately and is taken down.
- **Dropping works without global button state**: without access to the input devices, the X11 drag source never saw the button release and waited for the 30-second timeout. It now falls back to X's own button state and drops normally.
- **Fewer window queries while dragging out**: the XWayland hover check during a drag-out went from every 50 ms to every 200 ms, which keeps dragging light.
